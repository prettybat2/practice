# 추석 도미노 영상 프로젝트 브리프

> 이 파일은 Claude Code가 이 폴더를 열면 자동으로 읽는 프로젝트 브리프입니다.
> 작업자: 루이 (편집디자이너, 파이썬·JSX 자동화 경험 있음). 대답은 항상 존댓말로 합니다.

## 1. 목표

Blender 물리 엔진으로 "구슬이 굴러가 도미노를 쓰러뜨리고, 거대한 도미노 벽이 넘어가면서 추석 그림이 드러나는" 세로 쇼츠 영상을 만든다.

- 참고 레퍼런스: YouTube TM Domino 채널 "AMAZING Rainbow Dominoes! | Satisfying Domino Screen Link" (실사 도미노 스크린)
- 최종 그림: `assets/chuseok_cats.png` — 한복 입은 고양이 셋, 문구 "즐거운 추석 보내고 계신가요?"
- 규격: 1080×1920 (9:16), 30fps, **약 60초** (2026-09-26 20초 → 60초로 확장)
- 원하는 느낌: 다채롭고(무지개색), 다이나믹하고(구슬·분기·슬로모션), 도미노가 **실제로 부딪혀서** 쓰러질 것 (닿기 전에 혼자 쓰러지면 안 됨)

## 2. 확정된 구성 (60초 버전, 2026-09-26 확정)

루이 요청: "더 디테일하고 구성이 다양하게" — 제안한 장치·추석 소품을 **전부** 넣고, 질감도 실사처럼.
장치마다 **따로 물리 계산**하고 카메라를 바꿔 이어 붙인다 (한 번에 수천 개 계산은 너무 무거움. 실제 도미노 쇼 영상도 컷을 나눔).

| 시간 | 장면 | 스크립트 |
|---|---|---|
| 0–6초 | 송편 구슬이 나선 레일 → 깔때기를 돌아 내려옴 | `scene01_marble_seesaw.py` |
| 6–10초 | 구슬이 시소에 떨어지고, 반대편이 첫 도미노를 침 (슬로모션) | 〃 |
| 10–17초 | 커지는 무지개 S자 줄 → 계단 오르내리기 → 다리로 다른 줄 위 교차 | `scene02_*` |
| 17–23초 | 3층 피라미드 붕괴 | `scene03_*` |
| 23–28초 | 윷가락 도미노 4개 → 윷 던진 듯한 연출 | `scene04_*` |
| 28–36초 | 위에서 본 보름달 나선 필드, 쓰러지며 보름달 무늬 | `scene05_*` |
| 36–42초 | Y자 분기 → 양 갈래 끝에서 송편 구슬 두 개 밀어냄 | `scene06_*` |
| 42–54초 | 구슬 두 개가 그림 벽 양쪽 아래 모서리를 동시에 침 → 금색 급전선 → V자로 퍼지며 고양이 그림 | `scene07_*` |
| 54–60초 | 원본 그림으로 부드럽게 전환 + 종소리 | 편집 |

- 구슬은 **송편 색**(분홍·연두·노랑·흰색) 반투명 유리구슬.
- 배경: 보름달 밤, 한옥 마루(나무 바닥), 따뜻한 등불 조명.
- 이전 v4 구성(`reference/v4_composition_reference.mp4`)은 흐름 참고용으로만 남겨 둔다. 파이썬으로 흉내 낸 그래픽이라 물리·그림자가 가짜다.
- 이전 의견 유지: 벽은 가운데보다 **모서리에서 시작**, 도미노는 **다채롭게**.

## 3. 작업 환경

- Windows, **Blender 5.0 계열** (무료, blender.org)
- 그래픽카드 **AMD Radeon RX 9060 XT** (RDNA4)
  - 기본 렌더러는 **Eevee** (빠르고 이 장면에 충분)
  - 사실적인 유리구슬 컷이 필요할 때만 Cycles + **HIP** (Preferences → System → HIP)
- 명령줄 실행 예 (경로는 설치 버전에 맞게 확인):
  `"C:\Program Files\Blender Foundation\Blender 5.0\blender.exe" -b -P scripts\파일.py`
  - `-b`는 창 없이 실행. 물리 검증은 이걸로, 렌더는 `-a`(애니메이션) 또는 특정 프레임만 `-f 번호`
  - 스크립트 인자는 `--` 뒤에: `blender -b -P scripts\look_test.py -- render 1 45` (해당 프레임 스틸 렌더)

### 클라우드(Claude Code 원격) 작업 환경

- PC가 아니라 클라우드 컨테이너에서 Claude가 스크립트 작성·물리 검증·미리보기 렌더를 한다.
- Blender는 `pip install bpy` (5.0.1, Python 3.11)로 설치 → `python3 scripts/파일.py`로 실행. **세션이 끝나면 사라지므로 새 세션마다 재설치.**
- GPU가 없어 **Eevee는 실행 불가**(libEGL 없음, 멈춤). 환경변수 `DOMINO_PREVIEW_CPU=1`을 주면 `domino_lib.render_setup()`이 Cycles CPU로 바꾼다 (540×960, 24샘플, 한 장 약 12초).
- 최종 본 렌더는 루이 PC(Eevee 또는 Cycles+HIP)에서.

## 4. 물리 설정에서 이미 배운 것 (중요)

- `bpy.ops.object.transform_apply()`는 기본값이 **위치·회전·크기 모두 적용**이다. 크기만 적용하려면 반드시
  `transform_apply(location=False, rotation=False, scale=True)`.
  이걸 틀리면 모든 도미노의 충돌 판정이 원점에 겹쳐 **첫 프레임에 폭발하듯 날아간다.**
- 구슬이 도미노 아랫부분을 치면 발이 밀려 **도미노가 뒤로 넘어진다.** 해결한 값:
  - 구슬 반지름 0.3, 질량 0.3 / 도미노 1.0×0.5×0.15, 질량 0.2, 마찰 0.8 / 바닥 마찰 0.8
  - 도미노 간격 0.6
- 강체 월드: `substeps_per_frame = 20`, `solver_iterations = 30`
- 도미노 1.0 높이는 실제 1m 스케일이라 쓰러짐이 느리다. 속도감이 필요하면 스케일을 줄이거나 중력/시간 배율을 조정.
- `scripts/domino_test.py` = 검증 완료된 기본 테스트 (구슬 + 도미노 10개, 끝까지 연쇄 확인됨)
- **속도감: 강체 월드 `time_scale = 2.5`** 가 실제 도미노처럼 보인다 (1.0이면 25개에 8초로 너무 느림).
- 크기가 변하는 도미노: 간격 = 높이 × 0.6, 질량 = 0.2 × 크기³. 0.55배 → 1.45배로 커지는 S자 줄 25개 전부 앞으로 쓰러짐 확인.

## 4-1. 공용 라이브러리 `scripts/domino_lib.py`

모든 장면 스크립트가 `import domino_lib as D`로 쓴다.
- `reset_scene(frames, time_scale)`, `add_rigid()`
- `make_domino(loc, yaw, scale, rgb)` — 모서리 둥근(베벨) 플라스틱 도미노. 크기별 메시 공유, 색은 오브젝트 단위 재질
- `path_points(fn, t0, t1)` + `dominoes_along(points, scale_fn, color_fn)` — 곡선 따라 깔기
- `plastic_mat`, `glass_marble_mat`(송편 구슬), `wood_mat`(마루), `rainbow(t)`
- `wood_floor()`, `night_lighting()`, `camera(loc, target, lens, dof_fstop)`
- `render_setup(scene, preview)`, `render_still(scene, frame, path)`
- `verify(scene, objs)` — 프레임별 쓰러진 개수, 서 있는 것/뒤로 넘어진 것 목록
- 디테일 도미노는 **점(pip) 없는 단색**이 맞다 (TM Domino 같은 쇼 도미노는 점이 없음).

## 5. 작업 방식

1. 스크립트를 수정하면 **먼저 `-b`로 물리만 돌려서** 모든 도미노가 앞으로 쓰러졌는지 수치로 확인한다 (각 도미노의 기울기 각도를 프레임별로 출력).
2. 통과하면 저해상도(예: 540×960)로 몇 프레임만 렌더해 `renders/`에 저장하고 직접 확인한다.
3. 괜찮으면 루이에게 보여 주고 방향을 확인받은 뒤 본 렌더.
4. 렌더 결과물은 `renders/` 폴더에 저장.

## 6. 진행 상황 / 다음 단계

- [x] 공용 라이브러리 + 질감 테스트(`look_test.py`, `renders/look_test_f*.png`) — 루이 확인 완료
- [x] 장면 1: 송편 구슬 나선 레일 → 깔때기 → 시소 → 첫 도미노 (`scene01_marble_seesaw.py`, 도미노 21개 전부 통과, 약 15초 분량 → 편집에서 줄임)
  - 배운 점: 깔때기는 원뿔보다 **중력 우물 곡선** `z = -K(1/r - 1/R)`(K=0.55)이라야 구슬이 원을 그리며 돈다
  - 구멍 아래에 **관**을 달지 않으면 구슬이 옆으로 튀어 시소를 비껴간다
  - 시소는 경첩(HINGE) 제약, 판자 양옆에 **턱(홈)**이 없으면 구슬이 옆으로 굴러떨어진다
  - 아직: 카메라가 너무 멀다(연출 단계에서), 나선 가로대가 레일에 안 닿아 보임
- [x] 장면 2: S자 → 계단 → 다리 교차 (`scene02_stairs_bridge.py`, 83개 전부 순서대로 통과)
  - 계단: 한 칸 = 도미노 간격(0.57), 높이 0.2(도미노 높이의 1/5)면 오르내리기 모두 안정적
  - 다리 상판 아래는 비워서 줄 앞부분이 그 밑을 지나감. 장면 시작은 `D.lean()`으로 첫 도미노를 살짝 기울임
  - 라이브러리에 `plan_along(align_end=True)`, `build_plan`, `polyline/arc/straight`, `box`, `lean` 추가
- [x] 장면 3: 피라미드 (`scene03_pyramid.py`, 서 있는 101개 + 가로판 30개, 전부 붕괴)
  - 한 줄 → 쐐기(1→5칸) → 6/4/2칸 3층 피라미드, 6줄
  - **가로판은 반드시 좌우(x) 방향으로** 같은 줄 두 칸만 덮을 것. 앞뒤 두 줄을 묶으면 첫 줄이 꿈쩍 안 함
- [x] 장면 4: 윷가락 (`scene04_yut.py`, 도미노 43개 + 윷가락 4개, 결과 "윷")
  - 윷가락 = 반원 기둥(높이 2.3), 둥근 등이 앞·X무늬 배가 뒤 → 앞으로 넘어지면 배가 위로 = 윷
  - 갈래 줄은 1.0 → 1.6배로 키워야 무거운 윷가락을 넘김. `align_end`를 쓰면 시작 간격이 벌어지니 주의
  - 연출: 앞쪽 낮은 각도(등만 보임) → 위에서 내려다보는 컷으로 "윷" 공개
- [x] 장면 5: 보름달 나선 필드 (`scene05_moon_spiral.py`, 156개 5바퀴, 전부 순서대로)

  - 위에서 내려다보는 컷은 조명이 세서 색이 날아감 → 노출 -1.2
